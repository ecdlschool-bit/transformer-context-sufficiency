# Reproducibility Guide

This repository separates lightweight analysis reproduction from full experimental reruns.

## 1. Fastest verification

Run:

`reproduce_paper.ipynb`

This notebook reads the archived outputs in `results/`, regenerates the reported summary tables and figures, and performs numerical integrity checks. A successful run ends with:

`PAPER REPRODUCTION FROM EXISTING RESULTS: PASS`

The companion file

`reproduce_paper_executed.ipynb`

contains the same analysis with stored outputs for immediate inspection.

## 2. Analysis environment

For a pinned, headless CPU analysis environment (Python 3.12), install:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell instead:
# .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-analysis.txt
python scripts/verify_inputs.py
python scripts/run_reproduction.py
```

The runner creates a fresh temporary working directory containing only the fourteen
declared result inputs. It starts a kernel using the same Python interpreter,
executes all analysis cells, and exits with an error if any numerical check
fails. It saves figures, tables, the executed notebook, and a validation report
in a new `validation-run/` directory. To repeat, supply a new directory with
`--output validation-run-2`. No retraining, external data, or model downloads
are required. The output directory must not already exist, preventing stale
figures from satisfying the checks.

For interactive use, the existing installation below is also supported; the
pinned file above defines the analysis verification stack.


Install:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

The analysis-only workflow requires the archived outputs and does not retrain models.

## 3. Full experimental reruns

Experiment notebooks are stored in `notebooks/`. Install the additional experiment dependencies with:

```bash
pip install -r requirements-experiments.txt
```

GPU-enabled PyTorch builds should be selected for the local CUDA environment.

## 6. HMM correction

The final HMM information gap is computed from matched/same-history quantities. Older differences between independently estimated Monte Carlo cross-entropies can be slightly negative from sampling noise and are not used in the final analysis.

The authoritative corrected calculation is implemented in `HMM_Information_Gap_Correction_GPU.ipynb` and archived in `HMM_Oracle_Gap_Fix_GPU_RESULTS.zip`.

## 7. Numerical checks and integrity

`reproducibility/inputs.sha256.json` records the exact analysis inputs from
commit `c097b1d6a64d70d43990558d282a6812f7e1c591`. The verifier checks every
SHA-256 and ZIP member CRC before execution. This is the source commit of the
result data, not the commit of later documentation changes.

The analysis notebook checks stored experiment audits, six A1/A4 numerical
references (absolute tolerance 5e-6, relative tolerance zero), and four corrected
HMM references (relative tolerance 2e-6, absolute tolerance 1e-15). It also
requires all 15 PNG figures to exist in the fresh output directory. Figure
pixels are not required to be bit-identical across fonts/rendering platforms.
These checks cover selected numerical fingerprints, not every manuscript
sentence or table cell. Any failed final check raises an exception after saving
the audit.

remain the archival reference.

The archival deposit designated in the article has the reserved DOI
[10.5281/zenodo.23528707](https://doi.org/10.5281/zenodo.23528707). Its prepared
files are the frozen repository ZIP and the complete
`HMM_Latent_State_Extension_RESULTS.zip`. A reserved DOI or private draft preview
is not a published archival record; publication of the existing draft is needed
for public access. Repository documentation does not itself publish the deposit.

The full HMM archive is optional for CPU analysis: the required native/probe
summary CSVs and corrected gap ZIP are already in `results/`. The complete
archive retains configuration, run JSON, CSVs, figures and checkpoints for
provenance. Historical HMM intermediate outputs are not the authoritative
corrected same-history result.

The prepared delivery manifest records the original snapshot commit and
SHA-256 checksums of the snapshot ZIP and full HMM ZIP. Preserve those files
and checksums when publishing the existing archival draft. Later metadata
updates are separate from the frozen research artifacts.

## Revision corrections and raw-data provenance

The original ten archives/CSVs retain their original checksums. Four additional
inputs are now supplied from the original experiment exports: the stationary
baseline audit CSV, corrected shuffled-label archive, V32-k3 scaling archive,
and the 2,400-row `reviewer_R1_5_HL_uncertainty_raw.csv` recovered from the
Jupyter server. The manifest identifies both provenance groups explicitly.

The reproduction notebook now recomputes Part I summaries/contrasts from the
clean per-run publication table, targeted scaling from its raw CSV, and Qwen
summaries/contrasts from raw probe losses joined to the stationary baseline
audit on k/L/seed. It updates the shuffled-label columns using the corrected
ten-seed results. Older summaries inside immutable archives are historical
inputs, not the authoritative final analysis. Model-size differences are
descriptive because token maps are sampled independently across checkpoints.

Monte Carlo uncertainty is computed separately within each source kernel
(V, k, L, source_seed, N), with 20 repetitions per condition. The standard
deviation across those repetitions, its standard error, and the approximate
normal 95% halfwidth (1.96 SE) are exported. Pooling different source kernels
would conflate source variability and Monte Carlo error and is not used for
the manuscript's precision statements. At N=500,000 the within-kernel SD range
is 0.0002063852-0.0004044759 and maximum halfwidth is 0.0001772694 nats.

The 44 checks include six corrected Table 4 readout values, the corrected
shuffled-label ranges, and raw Monte Carlo completeness/identity/uncertainty
checks, in addition to the original checks. They are selected numerical and
artifact checks, not a full new GPU experiment or a proof of every claim.
